## 1. 核验口径

- 商业能力以原厂产品页、帮助页、公告和更新日志为主。OpenAI 先用 OpenAI Docs 搜索，再读取匹配正文。
- 维护者的 README、版本说明与源码差异用于判断“有何实现或声明”，不当作运行成绩。
- Today 关于 Duet 的文章代表竞争者观点，仅用于寻找线索；具体能力仍回到 Anthropic 原文。
- 25 个仓库均查询默认分支 HEAD。7 个主样本读取固定 HEAD 的 README，6 个有变化的主样本及 Celesto 读取比较接口。其他未变化仓库只确认 HEAD，组件仓库以活动监测为主。
- 比较区间是“上版固定提交 → 本次固定提交”。其中可能包含晚合并、作者日期更早的分支。不能按作者日期判断已进入默认分支的时间。
- 没有安装、运行、连接私人账号、发送外部消息、付款或做渗透测试。下文的验证方案尚未执行。

## 7. 静态读取的深度与限制

- 七个主样本均重新读取固定 HEAD 的 README。OpenMuse、OpenDots、chyroc、open-instinct 的 README 与本地旧缓存逐文本比较一致；不能据 README 不变推导代码或外部服务不变。
- OpenMuse 比较 API 返回 19 个提交、33 个文件；OpenBot 为 15 个提交、280 个文件。读取差异与版本文档只用于识别变化，并未逐文件审计。
- nanoMuse 的比较 API 标出 357 个提交，本次该页返回 100 个提交、300 个文件。**这不是完整差异审计。** 因此关键结论另用 1.0.7 发行说明、版本化隐私文和 iOS 上传代码确认。
- iOS 的自带密钥记录代码明确检查已登录和 `recordOn`。这一静态证据不能代表所有平台、所有部署都无条件上传，也不证明退出、删除路径已经跑通。
- OpenGrokBot 的安全文与 `gateway/src/agent.ts` 同时核对。源码有 watch 工具清单及拒绝分支；普通浏览器仍保留“审批约定不等于全部动作强制拦截”的自述。
- Celesto 重新读取子应用 README；不能把 Celesto 基础库新版本直接算成个人助理功能。
- 除注明的应用 README、关键文档与差异之外，构建组件主要查询 HEAD 和少量 release，不把全部旧功能、协议或许可重新盖上新日期。
